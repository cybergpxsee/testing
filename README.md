# 观察名单版（路线 ③）

## 它做什么 / 不做什么
做：把「到今天为止，某标的是否完成了一次破底翻」以及关键水平的位置，**作为事实列出来**。
不做：不判断"该不该买"、不判断回踩深度够不够 —— 那部分交给你。

## 本地跑（推荐先用这个）
    python examples/monitor_run.py
会打印并写出 `retest_watchlist.csv`，每行字段：
  双底左右脚日期 / 破底日 / 翻回日 / 破前高日 / 见顶日 / 见顶距今几根
  fib深(以底部区上沿为腿) 与 fib浅(以打破处为腿) 两个 0.618
  下降趋势线现值 / 今日最低价 / 今日收盘 / ATR
  到上述三个水平各多少 ATR（正=还没到，负=已刺穿）
  破底前箱体是否存在+持续根数 / 收盘是否已跌破底部区上沿
展示过滤（可在文件顶部改）：见顶后 25 根内、且今日最低价距任一水平 <=2.5 ATR。

Actions → pullback-scan → Run workflow → `scanner_module` 选：
  - `retest_watch`  观察名单模式（已接入模块选择）
  - `retest_scan`   带触发判定的 A 版（r2）
  - `us_pattern_scan` 原扫描器
注意：retest_watch 的 CSV 落盘那段我这轮没接完（插入锚点没匹配上），
所以 Actions 里请用 `retest_scan`；日常建议直接本地跑 monitor_run.py（数据用
fetch-history 导出的 data/history/）。

## 已知问题（我没掩盖）
1. 名单密度 34.5% 太高：一条链成立后能连续几周留在表里，因为"结构有效"的条件很松。
   要收紧就得选一个门槛，而唯一有依据的是"破底前有长箱体"——但你的 13 个圈里
   只有 BTC 和 MRNA 满足长箱体（62 根 / 115 根），HOOD/SIRI/P/棉花/TSLA 都不是长箱体。
   所以这条**不能当硬门槛**，否则你的买点会被砍掉一半。
2. 箱体列依赖收盘价直方图，棉花这类 volume=0 的存档也能算（已不依赖量）。
3. 只有 7 个标的、16 个圈，样本太小，任何"精确率"数字都不可信。要判生死，
   需要 5~10 个"当天明显不该买"的反例。
